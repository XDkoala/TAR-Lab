## FIX-001 只读目录写入失败

### 现象和影响

circpack 后续消融阶段生成的插桩副本在评估器调用 solution() 的路径中尝试保存结果，目标位于只读候选目录，导致对照评估失败。先前对话曾将其简称为“日志写入”，这里更准确地记录为结果文件写入。

### 原因和已做处理

生成代码的输出方式不符合评估环境约束。本次修复限定在生成的插桩副本：仅在显式提供 results_dir 时导出结果；保留原始候选、求解逻辑及公开评估器。失败产物已归档，修复后四个标准消融配置完成。

这证明本次副本可以运行，不证明后续生成代码均能避免此错误。系统已有提示和重试机制在此路径中为何未能恢复，仍需定位，不能直接断言整个项目没有相关机制。

### 后续验收要求

明确区分只读源码目录、临时目录和持久结果目录；梳理现有接口后统一输出约定。增加与真实评估权限一致的小规模预检。覆盖不显式导出时正常返回、显式导出到可写目录、错误地写只读目录、修复预算耗尽四种情况。

如引入自动恢复，应保存原始错误与修复差异，限定次数，修后重新跑正确性检查。不得通过把源码目录改成可写、吞掉异常、绕过评估或删掉失败记录来宣称解决。

## FIX-003 TeX 路径检查误判

### 现象和原因

Debian 将 /usr/share/texmf/web2c/texmf.cnf 链接至 /usr/share/texlive/texmf-dist/web2c/texmf.cnf。两个目录均在允许范围，但原检查要求链接解析后仍属于同一个允许根目录，错误拒绝了合法输入。

### 已做处理与验证

同时修改宿主编排器和独立检查脚本：原始路径须位于允许目录，已存在路径解析后的目标也须位于允许目录集合，允许合法根目录之间的跳转，继续拒绝越界。

涉及项目文件：

- engines/ai-scientist-v3/src/orchestrator/paper_step.py
- engines/ai-scientist-v3/src/agents/skills/validate-paper/scripts/validate_compile_inputs.py
- engines/ai-scientist-v3/tests/paper/test_paper_step_evidence_latex.py

补丁曾作为提交 e70c595 应用（2026-11-18 起论文阶段已随引擎精简删除，见 FIX-005）。已补测试覆盖跨允许目录链接、链接到外部文件、从未批准位置链接到允许文件。相关测试 13 项通过；当时完整测试结果为 2207 passed、1 skipped，Ruff 和 Mypy 通过。这些是此前修复的验证记录，本次建档没有重新运行测试。

### 后续维护

保留现有改动，核查两套实现的一致性。只有在新改动影响此路径时补充验证，禁止直接关闭路径检查。

## FIX-006 论文改用本机 TeX Live 编译并增加投稿前检查（2026-11-18）

- **类别**：缺陷修复（构建环境与投稿环境不一致）。
- **原因**：FIX-005 之后论文只用 Tectonic 编译。Tectonic 基于 XeTeX，而 arXiv 和会议系统用 TeX Live 的 `pdflatex`：字体加载和断行不同（例如 IEEEtran 在 `pdflatex` 下用 Times 类字体），本地页数、溢出和字体嵌入的结果不能代表投稿时的结果；也没有任何检查能发现未定义引用、未嵌入或 Type 3 字体、超页和匿名泄露。
- **修改**：在 `../.tools/texlive/2026` 无 sudo 安装 TeX Live 2026（scheme-full，不含文档和源码，4.9 GB，清华 CTAN 镜像，安装命令见 README）。`tar_lab/tools/tex.py` 的引擎顺序改为本机 TeX Live（`latexmk -pdf -no-shell-escape`，可用 `TARLAB_TEXLIVE_BIN` 覆盖）→ `PATH` 上的 `latexmk`/`pdflatex` → Tectonic；`build.log` 第一行和 `TexBuild.engine` 写明所用引擎。新增 `tar_lab/tools/paper_check.py` 和 `tarlab tex check`：去掉编译产物后在临时副本中编译，检查日志（错误、未定义引用、缺失文件、>1pt overfull、字体替换）、`pdffonts`、`pdfinfo` 页数、`.bib` 键和字段，可选匿名检查，有 FAIL 时退出码为 1。写作和评审指南要求运行该检查。
- **验证**：ruff、mypy、全部测试通过（新增 `tests/tools/`，需要真实 TeX 的测试在无安装时跳过）。IEEEtran 小论文：10 项全部 PASS，`pdffonts` 显示 NimbusRomNo9L（Times）全部嵌入，无需额外宏包。Project B 论文副本（`/tmp` 中）：编译通过，19 个字体全部嵌入、6 页；WARN 为 3 个 bib 条目缺年份和匿名检查（作者栏、引用的第三方 GitHub 链接）。人为加入未定义引用和缺失图片的副本被判为 FAIL，退出码 1。
- **剩余风险**：arXiv 当前默认 TeX Live 2025，本机是 2026，个别宏包版本可能不同；匿名检查是关键词启发式，会把引用的第三方 GitHub 链接也报为 WARN；参考文献起始页只是尽力识别。
- **回退**：`git revert` 本次提交；删除 `../.tools/texlive` 后会自动退回 `PATH` 上的 TeX 或 Tectonic。

## 自动修复能力的建设顺序

1. 先让错误可复现、可分类，并有明确的输入输出约定。
2. 增加廉价预检，在正式计算前发现常见问题。
3. 对明确且局部的问题开放有限次数的自动修复，保留原始程序和差异。
4. 在隔离副本中验证功能、结果正确性和现有边界，失败则停止或回退。
5. 将通过验证的案例沉淀成回归测试和修复记录，再考虑扩大自动处理范围。

自动修复不能以改变科学目标、降低评分标准、篡改证据或扩大权限为代价。新增修复规则也需有适用条件，不能把某次实验的特殊处理无条件推广。
